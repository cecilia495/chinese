# 餐厅主题课程数据审计

## 教学任务与发布状态

| 等级 | 大纲任务依据（印刷页） | 本课程的可观察目标 | 当前状态 |
|---|---|---|---|
| HSK 1 | 问答饮食喜好，第 3 页 | 表达想吃、想喝什么 | 现有课覆盖 |
| HSK 2 | 问答日常饮食，第 7–8 页 | 询问菜品、比较或选择，说明数量并确认价格 | 现有课覆盖问菜和选择；数量及价格确认需要新增口语练习 |
| HSK 3 | 交流饮食情况，第 11–12 页 | 根据菜单提出具体要求，调整订单，核对价格，复述点餐经过 | 现有课覆盖菜单和总价；调整及复述待开发 |

课程目标是对大纲任务的教学转化。教材词表中「还是」为二级第 352 条，选择问句见二级语法第 387 页。「菜单」「碗」「一共」是三级新增词。低等级如用菜单图片，可以把「菜单」视为阅读支援，避免把识别菜单的任务误记为一级或二级词表收录。

HSK 2 的草案用「两个包子」「多少钱」练习数量和价格。「两1」「个」「包子」「多少」「钱」均可在大纲词表按编号追溯。「份」未列入这份 HSK 1–3 提取表，若口语试点使用「两份」，须视为场景拓展。

## 覆盖结果

- 重新从官方 PDF 提取并逐号比对了编号、词形、拼音、原等级标签、词性与页码。1–1000 连续，比对通过，分级计数为 300、200、500。
- 三份草案关联 50 个不重复编号。其中 8 个是当前上线课程的目标词，42 个是新增辅助词候选，因此草案词汇关联率为 5%，现有目标词关联率为 0.8%。
- 950 条未进入餐厅草案。原词表中 142 条核查标记继续保留。提取一致性验证未覆盖词义审校、音轨逐句审音或全话题归类。

## 复现

在 Python 环境中安装 PyMuPDF。由仓库根目录运行：

```sh
python scripts/audit-dining-curriculum.py /path/to/3.0_新版HSK考试大纲.pdf
```

数据位于 [dining-curriculum.json](../curriculum/dining-curriculum.json)。本轮为课程数据草案，未改变已发布的课程或音轨。

## HSK 2 数量和价格练习

审查分支加入 `/learn/order/` 独立练习，从 HSK 2 课程进入。学生先听店员的单价和提问，再口头表达并选择两个或三个包子。问价后可听对应报价、核对价格、听确认示范并自行录音。六段新音频使用云扬店员和晓晓顾客。价格核对是选择题，录音回听用于自查。既有课程的会话记录仍使用原机制。

生产构建和 TypeScript 检查通过。375、1280 像素宽度的 Chromium 验证了两种数量、错误价格反馈、更换数量后重置、报价播放及返回 HSK 2。六段音频通过解码检查。未测试真实设备麦克风和专业听审。该练习尚未部署到公开站点。

## HSK 3 说明理由与换饮料练习

审查分支从 HSK 3 课程链接到 `/learn/change-order/`。学生用「太甜了」说明原因并请求换水，听出店员误换成茶后纠正，最后用「太……了，所以……」复述经过。活动使用选择反馈和本地录音回听，未提供自动口语评分。

生产构建通过。375、1280 像素宽度的 Chromium 已验证缺原因或请求的反馈、店员音轨播放、纠正饮料选择、模拟麦克风录音生成和返回主课。六段云扬／晓晓音频已通过解码检验。本次未使用真实设备麦克风，尚未部署到公开站点。

## 口语活动入口与记录

首页与「我的学习」新增 `/activities/`。两项活动支持从目录直接开始、返回课程及再练。答对价格或纠正换饮料的误解之后，目录显示「情景选择已核对」。此标记仅记录本标签页中的选择结果，录音与口语水平不由此判定。

生产构建通过。375 和 1280 像素宽度的 Chromium 已通过活动导航、错误选择不计入、正确选择记录、刷新恢复、阿拉伯语 RTL 布局与新浏览上下文为空检查。

## HSK 1 吃喝问答活动

从目录或 HSK 1 课程进入 `/learn/food-drink/`。学生先听店员问想吃或想喝什么，再开口练习并选择对应答句。两轮答对后可录下「我想吃……」「我想喝……」并回听。两个新提示使用云扬，答句沿用在课内使用的晓晓录音。

生产构建通过。375、1280 像素宽度的 Chromium 已验证播放、错误答案不能继续、两轮正确答案后才写入活动记录、模拟麦克风录音及目录状态。真实麦克风未测试。活动属于审查分支，尚未公开部署。
